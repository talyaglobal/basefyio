## What's fixed

- **A session setting from one client no longer reaches the next one.** The pooled connection (port 6432) shares server connections between clients. Until now, a session-level `SET`, such as `SET default_transaction_read_only = on` in a psql one-liner, stayed on that server connection. Your other clients on the same pool then failed every write with "cannot execute INSERT in a read-only transaction". The pooler now runs `RESET ALL` when a server connection goes back to the pool. Prepared statements are kept.
- To change the reset, self-hosters can set `PGBOUNCER_SERVER_RESET_QUERY`. An empty value in `.env.production` turns it off. See the configuration reference.

## What's new

- **Send every auth e-mail from your own app.** A new e-mail provider option, **None — my app sends the e-mails** (`emailProvider: "none"`), stops the platform from sending any auth mail for the project: verification, password reset, magic link, invitation, e-mail change and welcome. Your server creates the links and codes with the service key through `POST /api/auth/v1/admin/generate_link` and sends them with your own mailer. Turning off e-mail verification only skipped the sign-up mail.
- **Find a user by exact address.** `GET /api/projects/:projectId/auth/users?email=` returns only the user with that exact address. Capital letters don't matter. `?search=` still finds partial matches across several fields.

## Fixed

- **Upload URLs made with the service key work.** An upload URL created on your server with the service key was refused when the file was sent to it, unless anonymous users could write to the bucket. The upload now runs with the service key's rights.
- **Bad paths answer 400.** Downloading or signing a path with a `..` or `.` segment now answers 400 instead of a server error. File names that only contain two dots, such as `v1..2.txt`, still work.

## What's new

- **Social sign-in stays in your app.** First and last name are optional, so a GitHub or Google user is never asked to fill in a profile form on an identity-server page. Names are filled in from Google (`given_name`, `family_name`) and GitHub (`name`) when the provider has them. A cancelled or failed sign-in returns to your `redirect_to` with `#error=<code>` instead of a page on the API host.
- **Verified addresses from Google and GitHub.** These users get `email_verified: true`, also when the provider is linked to an account that signed up with a password first. A per-provider "Trust the e-mail address" switch is in Authentication → Providers.
- **`prompt` and `state` on `GET /rest/v1/auth/signin/:provider`.** `prompt` is `login`, `select_account`, `consent` or `none`. `state` comes back unchanged in the callback, and the query string of `redirect_to` is kept.
- **Sign out of the browser session.** `POST /rest/v1/auth/logout-url` returns a URL that ends the sign-in session and lands on your app, with no confirmation page when the callback's `id_token` is sent.
- **Resend the verification code.** `POST /rest/v1/auth/verify-email/resend` mails a new code; the answer is the same for any address and requests are rate limited.
- **Sign-up while verification is pending** answers `verificationRequired: true`. When sign-in is held until the address is confirmed it returns no tokens, where it used to fail with 401 after creating the user.
- **`GET /rest/v1/auth/me`** now includes `provider` and `providers`.

## Fixes

- Existing projects pick up the new defaults the next time a provider is saved, or through the auth repair action.

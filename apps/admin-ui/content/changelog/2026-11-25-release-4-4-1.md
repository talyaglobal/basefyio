## What's new

- **Named extra database roles.** Choose a short prefix once per project (for example `shop`) and create roles with names you control: `shop_app`, `shop_owner`. Every name is checked on the server: the prefix must be unique, and reserved names such as `anon`, `authenticated`, `service_role` and anything starting with `pg_` are refused. A project can have up to 10 login roles and 10 group roles. Roles without a prefix keep working exactly as before.
- **MCP tools and CLI.** `create_db_role`, `list_db_roles`, `reset_db_role_password` and `drop_db_role` for AI assistants, and `basefyio db roles create|list|reset-password|drop` in the CLI.
- **Every role change is logged** in the project's activity (who, which role, what), never with a password.
- **Roles are removed with their project.** Deleting a project now drops its extra database roles too; objects they owned are handed to the project owner first.
- **New guide** `docs/guides/extra-database-roles.md`: what an extra role is, how to create one, and why a role change through the pooler must be `SET LOCAL ROLE` inside one transaction.

## What changed

- **Passwords are no longer listed.** `GET` and `PATCH` on `/api/projects/:id/db-extra-roles` stop returning the stored role passwords to API tokens. A password is shown once when you create the role or rotate it, and the dashboard's reveal button is unchanged. If a script of yours read passwords from the list, store them when you create or rotate instead.
- **Rotating a password without choosing one** could fail now and then because the generated password was checked against the rule for chosen ones; that is fixed for owner, read-only and extra roles.
- **Fewer failed requests during a release.** Requests that cannot connect while a server is being replaced are retried on the next one, and unhealthy servers leave the pool after 3 seconds instead of 10. This is a one-time change applied with this release.

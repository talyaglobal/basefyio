## What's new

- **AI Agent mode asks before it changes anything.** Read-only queries still run on their own, now inside a read-only transaction that is always rolled back. Every statement that changes data or schema (tables, policies, inserts) is shown in full with **Run** and **Cancel**. Approved statements run in order and stop at the first error. A policy that would let anyone write is flagged, and you are asked again before it runs.
- **Agent answers report what really happened.** A line computed from the real results says how many statements succeeded, failed, were skipped or are waiting. The assistant is told the same facts, so it can no longer say a failed change was applied. Writes show the rows they affected.
- **Uploads no longer count as egress.** Traffic now counts only the bytes the platform sends back. Before, every upload was added to egress and used up the plan's bandwidth.
- **The project cost table adds up.** Usage from projects that were deleted or moved to another organization during the period appears as an **Other usage** row, so the table matches the Usage card.
- **Billing says how fresh each figure is.** Database size is measured every hour and file storage every 6 hours, and sizes are binary (1 GB = 1,073,741,824 bytes). Plan cards now list the database, bandwidth and monthly active user limits. A meter at 100% links to the plans.
- **New Project stops early at the project limit.** The dialog says the organization's project limit is reached before you fill it in, instead of failing after you submit.
- **Dedicated compute is listed as coming soon.** The Pro and Business cards no longer show dedicated infrastructure as included, because it cannot be set up yet.
- **Data editor page size.** The "Rows per table" setting is renamed, because it sets how many rows the Data editor loads per page. It never limited how many rows a table can hold.
- **Single-use refresh tokens (opt-in).** Under Auth > Policies a project can make each refresh token work only once. A reused token is refused. It is off by default and existing projects are unchanged.
- **`auth.uid()` can return uuid (opt-in).** On Database > Policies, **Switch to uuid** makes `owner uuid default auth.uid()` work. The switch is refused, and nothing changes, while any policy, default, view or function still uses the text version.

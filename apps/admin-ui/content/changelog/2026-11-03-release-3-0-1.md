## What's new

- **Secret keys.** Under **Connect → API Keys**, create as many named server keys as you need — one per server, CI job or environment. Each has the service key's access, is shown once when you create it, lists when it was last used, and can be revoked on its own: requests with it are refused from the next one.
- **Rotate the service key.** A new service key is created and shown once; the old one stops working immediately. Move a server to a secret key first and rotation costs it nothing.
- **Server keys stay hidden.** The service key is shown masked. You can reveal and copy it until an application first uses it; after that the dashboard keeps it hidden. Code snippets on the Connect, API explorer and embeddings pages no longer contain your key — paste a secret key where they say `<your-secret-key>`.

Server keys, secret keys included, are accepted only in the `apikey` header, never in a query string. Rotating and creating keys needs the team's credentials permission.

## What's new

- **Timestamps keep their microseconds.** Date and time columns (`timestamptz`, `timestamp`, `date`, `time`, `interval`) and `bytea` are copied as text, so the value arrives exactly as it was. Before, they went through a JavaScript date and lost everything below the millisecond.
- **A read that fails is a failed table, not an empty one.** When a table could not be read from Supabase, for example because the database had no free connection slot, the import used to count it as zero rows and then try a second read that row level security empties out. A temporary failure is now retried with a growing pause, and any other failure is listed against the table with its reason, with the number of rows that had already been copied.
- **Schemas from a newer Postgres apply.** A schema dumped by a newer version carried lines this server rejects (`\restrict` and `SET transaction_timeout`). They are removed before the schema is applied.
- **You can import again over an existing project.** Every object that was already there was counted as a failure. Functions and views are now replaced, tables, indexes and sequences are created only when missing, policies and triggers are dropped and created again, and an object that is already in place is not reported. A statement that really fails is still reported, as you wrote it. Rows already in the project are never overwritten.
- **Fewer database connections during an import.** The import used up to ten connections to your project's database; it now uses at most four.
- **Create an auth user with a chosen id.** `POST /api/projects/<id>/auth/users` accepts an optional `id` (a UUID) and keeps it, so a user moved from another project keeps the id that rows in your database point at. The response returns the id of the user it created.

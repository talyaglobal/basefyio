## What's new

- **Monthly active users are counted.** Each organization's monthly active users are now tracked across all its projects and shown next to the other meters on the Billing page.
- **Database size stays current.** Every project database is measured hourly, so the size you see against your plan limit is no longer hours old.
- **Plan limits can be enforced, one metric at a time.** API requests, traffic, monthly active users and database size each have a mode: off, warn or enforce. In warn mode nothing is refused. Over a limit plus a 10% grace, enforcement answers `429` for requests and traffic until the month turns, `402` for new data and schema writes when the database is over its size, and `402` for new sign-ups when monthly active users are over. Deleting data, reading it, and existing users signing in always keep working, and owners get an e-mail at 80% and 100%. Legacy and grandfathered plans are never limited. Every limit starts in warn mode, so nothing changes today.
- **An Enterprise plan exists.** It is arranged by contact, with custom limits, and is not available for self-serve checkout. The pricing section has an Enterprise card, and the Billing page shows a contact line for Enterprise organizations.
- **Counting is more accurate.** Requests from Supabase-style client paths that used to be skipped are now counted, so figures for those clients rise. A failed usage flush no longer loses its counters, and the monthly reset is idempotent.
- Plan rows are no longer overwritten when the platform starts: a seed only creates a missing plan.

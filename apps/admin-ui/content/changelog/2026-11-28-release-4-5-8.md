## What's new

- **Vectors next to your document data.** A Data Engine entity can now hold one vector per record, stored alongside the record in the document store. Declare the width once with `PUT /api/v1/projects/{id}/entities/{entity}/vector-config`, write vectors you computed yourself (one at a time or 100 per request), and find the nearest records with `POST /api/v1/projects/{id}/data/{entity}/search`. Search uses cosine similarity, takes the same `filter` as listing records, and returns each record with its distance and score.
- **Exact results, with a published limit.** Search compares the query with every candidate, so results are exact. A search that would have to scan more than 10,000 vectors is refused with a clear message instead of returning partial results: narrow it with a filter.
- **Good to know.** These routes need the service key. Vectors are never returned by normal reads, and writing a vector does not change the record's version. The document store is not yet covered by platform backups, so keep the source you computed your vectors from.
- **Embeddings search filter fixed.** On the embeddings API, `filter` on metadata never matched any row. It now returns the rows whose metadata contains every key and value you name. `threshold` and `ids` are validated and answer `400` with a reason instead of an internal error.

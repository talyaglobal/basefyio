## What's new

- A realtime subscriber that connects with only the anon key now receives a row change only if the `anon` role may read that row under your row-level security policies. Before, anon subscribers were not checked, so a change to a table the anon key cannot read through the REST API could still reach them over the stream.
- Tables without row-level security are delivered as before. If an app relied on anonymous realtime for a table with RLS, add a `SELECT` policy for `anon` on it.

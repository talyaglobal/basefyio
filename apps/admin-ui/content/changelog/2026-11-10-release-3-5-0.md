## What's new

- Realtime UPDATE events now carry the row's primary key in `old` (for example `{ "id": 42 }`), so subscribers can tell which row changed. DELETE events still carry the whole row.
- A realtime stream with an unknown channel such as `foo:bar` now answers 400 instead of silently meaning "every table". A table or collection whose realtime is off is reported as `inactive` in the `ready` event with a `warning` event (`strict=true` makes it a 404).
- Data changes and broadcasts carry an SSE `id`. After a dropped connection the stream resumes with `Last-Event-ID` (or `last_event_id`) and replays what was missed from the last two minutes, or says `replay_gap` when it can no longer.
- Docs and the Realtime page now say where realtime is switched on, that service keys need the `apikey` header, and that SQL editor writes are not broadcast.

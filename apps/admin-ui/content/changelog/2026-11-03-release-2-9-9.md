## Fixes

- **Functions with arguments work.** `POST /rest/v1/rpc/<function>` now passes the arguments you send; before, a function that took arguments could not be called through the data API at all. Each argument is passed as the type the function declares, so the function that runs is always the one your argument names select.
- **A function called over GET or HEAD cannot write.** These calls run read-only. Call a function that changes data with `POST`.
- A malformed filter in a data API request now answers 400 with the reason, instead of 500.
- Changing a user's name or metadata in the dashboard no longer removes their e-mail and last name on the sign-in server, which had locked such users out with "Account is not fully set up".
- Progress views of long imports and exports stay connected while a step takes more than two minutes.

## What's new

- **Supabase-compatible auth and storage APIs** (`/api/auth/v1`, `/api/storage/v1`) for applications that use `@supabase/supabase-js` against basefyio. They are switched on per project; projects that do not use them are unchanged. Contact support to enable them for a project.
- The data API also answers PostgREST clients (supabase-js, postgrest-js) in their own wire format. basefyio's own SDKs and plain HTTP calls keep the current responses.

## What's new

- **Schedule triggers work.** Flows with `trigger.type: schedule` and a cron expression now fire at the configured time. A new `nextRunAt` field is stored on each flow and advanced after every run so the scheduler never double-fires. Invalid cron expressions now return 400 instead of being silently accepted.
- **Retries are visible.** When a flow run is retried by the queue worker, the `attempt` field (1 = first try, 2 = retry) is stored on the run record so the UI can show "attempt 2 of 2". The original `started_at` timestamp is preserved across retries instead of being overwritten.
- **Concurrent flow execution.** The flow queue worker now processes up to 10 runs in parallel. Previously a single slow HTTP step (10 s timeout) would block every other project's flows; now each project's runs are independent.

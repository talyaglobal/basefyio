## What's new

- **Tables with row-level security off are flagged.** Database > Policies reads each table's grants. When row-level security is off, it says in red who can read or change every row: anyone with your public key, or any signed-in user. A summary at the top lists every table that is open this way.
- **Tables outside `public` open correctly in the Data editor.** They are listed as `schema.name`, so they no longer mix with public tables or open a public table of the same name, and reading and editing rows uses the right schema. Rename, column changes and delete are offered for public tables only. Use the SQL editor for the others.
- **Large bulk inserts work.** An insert of more than 65,535 values (rows × columns), such as 10,000 rows of 7 columns, used to fail with "Internal server error". The API now writes it as several statements in one transaction, so all rows are saved or none are. Where it cannot split the insert, the request is refused with `400` and the number of rows that fit.
- **Skip the row count.** A REST read with `Prefer: count=none` no longer computes the exact total, which on a large table can take longer than the rows themselves. `count` is then `null`.
- **The embeddings store is hidden from the REST explorer.** The `kb_embeddings` tables belong to the Embeddings feature and are no longer offered as REST tables.

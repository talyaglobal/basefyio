## What's new

- **Start with tables, not an empty database.** When the **Find the right database** advisor suggests a starter, such as CRM, Inventory or Marketplace, step 2 now has a **Create these tables** box, ticked by default for relational projects. The project then starts with those tables. Each table has an id, an owner column that fills in the signed-in user, a creation time, its own columns, and links to the other tables. Change them as you like afterwards.
- **The same through the API.** Send `starter` with `POST /api/projects`, for example `"starter": "CRM"`. The tables follow your project's data access settings, as any table you create yourself would.
- **A starter never blocks a project.** If the tables cannot be created, the project is still ready, and the activity feed says so.

## What's new

- **Importing again no longer touches a live schema.** If the project already has tables, the import keeps its functions, policies, views and keys exactly as they are and copies data only. The import says so in its warnings. Before, it could replace tables, which removed their policies, views and keys and the rows written since the first import.
- **A table that already exists is never recreated.** This holds even when the schema could not be copied from the source.
- **A policy or trigger is only replaced by one that was created.** A replacement that is refused, for example because it compares a uuid with text, leaves the existing policy in place instead of leaving the table with fewer policies than before.
- **No foreign keys to a copy of `auth.users`.** Your users live in the project's identity service, so a key into a table of them refused every user who signed up after the import. These keys are left out and the import reports how many.
- **Users that could not be imported say why.** The warning now carries the real HTTP status and message from the identity service, not "Network response was not OK". A busy service is retried, and a source that returns no users says so instead of reporting nothing.
- **Clear errors for a missing function argument.** Calling a function that exists without one of its required arguments answers which argument is missing or unknown, instead of "Function not found".

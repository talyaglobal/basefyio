## What's new

- **Nightly backups work for projects with forced row-level security.** If a table in your project database has `FORCE ROW LEVEL SECURITY`, the nightly backup was refused by the database even for the table's owner, so no backup was produced for that project. Backups now run with the platform's own login, which row security does not apply to, so the backup contains every row. The backup is either complete or it fails with a clear reason.
- **Clearer failure reasons.** When a nightly backup fails, the project's activity log now shows the actual database error instead of the command line.
- **Nothing to change on your side.** Existing backups and restores keep working as before.

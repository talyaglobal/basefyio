## What's new

- REST upsert: a POST with Prefer: resolution=merge-duplicates (or ignore-duplicates) and optional on_conflict=<columns> inserts or updates in one request, under the caller's role and row-level security.
- REST responses: Prefer: return=minimal answers with no body (201 for an insert, 204 for an update or delete); an insert accepts select= to shape the returned rows; bigint columns are numbers like inside embeds (strings only beyond 2^53); a JSON-path column is named after its last key (meta->>color returns "color").
- REST input checks: limit and offset that are not whole numbers are a 400 instead of being ignored; a read that asks only for text/csv is a 406; Range headers page like limit and offset.
- REST errors name the failing constraint or input, and a denied write says whether a grant is missing or a row-level security policy refused it.
- Storage: listings take limit, offset, sortBy and order; new copy and rename routes; move, copy and rename refuse a malformed body with a 400; a signed URL for a missing object is a 404; a bulk delete counts only the objects that existed.
- Docs: the REST and Storage references describe the upsert, the 1000-row cap, the 60-second minimum signed-URL expiry and the new routes.

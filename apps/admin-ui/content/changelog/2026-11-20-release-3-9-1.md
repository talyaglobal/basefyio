## What's new

- **Expose more than `public` through the REST API.** Owners and admins list extra schemas with `PATCH /api/projects/:id/rest-schemas`. A request then picks one with `Accept-Profile` for reads or `Content-Profile` for writes. A schema that is not listed answers `406` with the allowed list.
- **Nothing changes unless you opt in.** Without the setting, and without the headers, the API serves `public` exactly as before.
- **Safe by construction.** System and platform schemas such as `auth`, `storage`, `extensions` and `pg_*` can never be exposed. Roles still need `USAGE` and table grants, and row-level security applies. Nothing is granted automatically.
- Writes outside `public` are not broadcast over realtime. The setting is API-only for now; a dashboard field follows.
